# 翻译助手（Translation Assistant）

一个 DeepSeek Harness 插件，在 Web 界面里加一张翻译工作台：翻译文本、图片或整份文件，逐段、逐句对照原文与译文，直接修改译文，还能随时切换模型，并把每篇文档留在本机。

[English README](README.md)

## 功能

- **对照工作台** —— 粘贴原文后一次请求同时译出段落与句子两种粒度：`逐段对比` 是默认视图，`逐句对比` 一键切换，切换本身不产生额外请求。
- **译文可编辑** —— 每个片段由原文块和译文输入框组成，两者等高拉伸，输入框随文字增高，不在框内出现滚动条。三种视图是联动的：在 `逐句对比` 里改一句，所属段落会按该段各句译文重新拼合，`逐段对比` 与 `全文` 立刻跟着变；反过来在 `逐段对比` 或 `全文` 里改一整段，会按句号等断句把这段拆回该段下的各个句子。句子数与断句数不一致时，多出的句子留空、相邻碎句合并，不会把句子从中间截断。
- **全文三种显示方式** —— `全文` 标签页支持 `译文`（默认，可编辑）、`原文`（只读）、`对比`（左右双栏，窄屏自动上下堆叠）。在全文框里的修改按空行切块写回对应段落，对照视图同步更新。复制全文与全文评分也在这里。
- **本机翻译历史** —— 每次翻译成功都会存成一条记录。右侧抽屉最多列出 200 篇文档，显示标题（原文首行）、最近使用时间、语言对和片段数。搜索同时匹配原文与译文（不区分大小写，空格分词为“且”），结果摘出命中处的上下文并高亮关键词。置顶只切换标记、不改最近使用时间；删除需要点两次确认。
- **图片 OCR 翻译** —— 粘贴截图或选择图片，视觉模型识别文字后填入原文框并翻译。上传前浏览器会把长边压到 2048px 并转成 JPEG。
- **文件翻译** —— `文件翻译`（或把文件拖进原文框）支持 `.txt`、`.md`、`.log`、`.html`、`.htm`、`.docx`，导入后直接整份翻译。文本按 UTF-8 读取；Word 文档在浏览器里就地解包（不依赖第三方库，也不上传原文件）后取出段落；HTML 先丢掉脚本、样式和 `<head>`，只把能看到的正文交给模型。导入的文件名会跟着文档保存，`全文` 里的 `下载译文` 会把结果写回文件：Markdown 存 `.md`，HTML 存成一段一个 `<p>` 的 HTML 文档（不保留样式与行内标签），其它存 `.txt`。
- **模型切换** —— 只要宿主的 LLM 注册表报出多于一个模型，头部的模型芯片就变成按 provider 分组的拉下框：`跟随默认模型` 继续跟随档案自身的默认选择，选其它条目则从这一刻起把该 provider/model 用于翻译、重译、评分和图片识别。选择记在本机，不会自动重做已经翻好的内容；原来选的模型不可用时会提示并切回默认，而不是让每次请求都失败。某个 provider 列举失败时会直接在编辑器上方说明原因，而不是留下一个没有下拉框的页面。
- **AI 重译** —— `AI 重译` 重做当前片段；`提示词重译` 可以带上“更口语化”“保留法律术语”这类要求。
- **按需 AI 评分** —— 每次打开页面评分都是隐藏的。`AI 评分` 评一个片段，`全部评分` 评当前视图（当前视图全部有分后按钮变为 `重新评分`），`全文评分` 评整篇，工具栏开关统一显示或隐藏。修改译文会清掉因此失效的评分。
- **按建议优化** —— 片段评过分后，`AI 评分 xx · 评语…` 这一行末尾会出现 `按建议优化`：把该段的分数和评语当作指令再译一次，出来的就是照评语改过的新版本，旧评分随之清空。当前视图全部有分时，工具栏还会出现 `全部优化`，一次把所有片段按各自的评语改完（并发 3 个请求，逐段回写，句子视图的改动照常合并回段落）。全文视图在 `全文评分` 之后，评语行末尾同样有 `按建议优化`，用整篇评语逐段重译整篇。三个视图都遵守同一条规则：**分数隐藏时不显示任何优化按钮**。
- **修改记录** —— 每份文档最多保留 20 份快照：机器翻译的初始版本、每次 AI 重译或按建议优化之前的版本、每次回退之前的版本，以及手动保存的版本。头部 `修改记录` 入口打开右侧抽屉，顶部是当前译文，下面是历次快照，每行标出它是什么时候、由什么操作留下的，并写明与当前译文有几处不同，附上译文开头。点 `回退到这里` 就把那一版放回文档；回退前会把当前译文先存一份，所以回退本身也能撤回。删除一条记录需要点两次确认。
- **Agent 工具** —— 同一套能力以 `translation_assistant` 工具暴露（`action: translate | retranslate | score | score_document`），可以在对话里直接翻译或评审文本。

## 日常流程

1. 粘贴原文（空行分段）、拖入 `.txt` / `.md` / `.html` / `.docx` 文件，或粘贴/选择一张图片。
2. 选好原文语言和目标语言；需要换模型时先在上方下拉框里切好，之后的重译、评分和识图都会用它。点 `开始翻译`。
3. 就地修改任意片段，或让 AI 重译（可附提示词）；评过分后还能点 `按建议优化`，让 AI 照着自己的评语再改一版。
4. 打开 `全文` 通读整篇译文，可以整篇编辑、复制、下载或评分。
5. 哪一版改差了就打开头部的 `修改记录`，回退到满意的那一版；回退前的译文也会存一条记录，随时能再回去。
6. 用头部的文档入口切回旧稿、把常用文档置顶，或点它右边的 `新建翻译` 开一篇新的。

## 实现结构

| 文件 | 作用 |
| --- | --- |
| `host/index.js` | 宿主侧：注册 `/dsh-translation/api` JSON 路由和 `translation_assistant` 工具，校验请求，解析模型路由。 |
| `host/engine.js` | 提示词构造、流式调用封装、重试、分批翻译（失败时逐段回退）、重译、片段与全文评分、图片 OCR。不依赖 Harness，可用假 LLM 流做单元测试。 |
| `client.js` | 浏览器侧：`main` 页面、侧边栏入口图标、全部交互状态与渲染。 |
| `cordis.patch.yml` | 插入宿主插件行。 |
| `locale/en.json`、`locale/zh.json` | 插件管理器的标题与描述。 |

页面通过同源请求访问宿主：

| 接口 | 用途 |
| --- | --- |
| `GET /dsh-translation/api/health` | 服务状态、当前模型名、档案默认模型、按 provider 分组的可切换模型列表，以及各 provider 的列举失败原因。 |
| `POST …/translate` | 一次请求翻译 `sentences` / `paragraphs` 两组片段。 |
| `POST …/retranslate` | 重译一个片段，可带 `extraPrompt`。 |
| `POST …/score` | 给一个片段打分（0–100 加一句评语）。 |
| `POST …/score-document` | 给整篇原文/译文打分。 |
| `POST …/ocr` | 识别图片文字（base64 图片 + 媒体类型）。 |

当 `Origin` 头指向其它来源时 POST 会被拒绝，请求体上限 24 MiB。每个 POST 都可带可选的 `route: { provider, model }`；不带时跟随配置或档案的默认路由。目录里没有的模型会在调用前以 HTTP 400 拒绝；只有目录本身为空（发现失败）时才放行，让模型服务自己判断。

## 配置

所有字段可选，写在插件行里（`cordis.patch.yml` 或插件管理器）：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `provider`、`model` | 当前默认选择 | 固定所有调用使用的模型路由。 |
| `reasoningEffort` | 未设置 | 可选的推理强度，透传给路由。 |
| `models` | 未设置（自动发现） | 给头部下拉框补充路由，例如 `[{ provider: deepseek-account, model: deepseek-pro, label: Pro }]`。会和宿主 LLM 注册表发现的结果合并，正在使用的路由总会在列表里。 |
| `targetLanguage` | `中文` | 默认目标语言。 |
| `sourceLanguage` | 未设置（自动检测） | 默认原文语言，页面可以覆盖。 |
| `maxTokens` | `8192` | 翻译调用的输出上限。 |
| `retranslateMaxTokens` | `4096` | 重译的输出上限。 |
| `scoreMaxTokens` | `4096` | 评分的输出上限。 |
| `ocrMaxTokens` | `4096` | 图片识别的输出上限。 |
| `maxRetries` | `1` | 供应商临时失败的重试次数。 |
| `scoreRetries` | `1` | 评分回复无法解析时的重试次数。 |
| `sentenceChunk`、`paragraphChunk` | `16`、`6` | 每批翻译的片段数。 |
| `concurrency` | `3` | 同时进行的批次数。 |
| `tool` | `true` | 设为 `false` 可隐藏 Agent 工具。 |

## 本机保存的数据

| 键 | 内容 |
| --- | --- |
| `dsh-translation-assistant:history:v1` | 最多 200 条（约 200 万字符），置顶优先，其余按最近使用排序。每条文档自带修改记录：最多 20 份、20 万字符。 |
| `dsh-translation-assistant:session:v1` | 上次打开的文档 id。 |
| `dsh-translation-assistant:prefs:v2` | 原文/目标语言、对照视图、全文显示方式，以及选中的模型路由（`null` 表示跟随默认）。 |
| `dsh-translation-assistant:document:v1` | 1.1.x 的单文档旧键：首次启动时并入历史后清空。 |

历史、编辑和偏好都只留在浏览器里；只有被翻译、重译、评分或从图片中读出的文本会发送到模型路由。清除该站点的浏览器数据会丢失历史，服务端没有副本。

## 限制

- 单次翻译请求最多 400 个片段；单个片段 20,000 字符；合计 120,000 字符。
- 修改记录每份文档最多 20 份、合计 20 万字符，超出后先丢最旧的快照。它也计入历史的总预算，改动很多的长文档可能挤掉更早的文档。
- 全文评分每侧最多 60,000 字符（合计 120,000）。
- 图片支持 PNG、JPEG、WebP、GIF，单张 12 MiB、单次请求 24 MiB。
- 导入文件单个不超过 8 MiB，取出的正文仍要满足 12 万字符的翻译预算。`.docx` 解包依赖浏览器的 `DecompressionStream`（Chrome 80+、Firefox 113+、Safari 16.4+），不支持时会提示改存 `.txt`、`.md` 或 `.html`。
- HTML 只翻译可见正文：脚本、样式、`<head>` 和属性都会丢掉。下载的 HTML 一段一个 `<p>`，不还原链接、加粗等行内标签。
- 评分要求模型稳定输出 `SCORE:` / `COMMENT:` 两行，也接受 JSON，形状不对会重试一次。评分是模型判断，不是权威指标。

## 开发与验证

本目录就是已安装的 bundle（档案直接链接到这里），所以改 `client.js` 会被产物监听器热替换到已打开的页面；宿主侧改动（`host/index.js`、`host/engine.js`）需要重启 Harness 后生效。

```bash
# 86 项单元/集成测试：引擎（翻译/重译/评分/OCR）、HTTP handler、模型目录发现与
# 路由覆盖，以及用极简 React harness 渲染的页面（不需要浏览器）。
node --test 'test/*.test.mjs'
```

维护提示：

- 页面会在请求前先按宿主限制做检查（400 片段 / 约 12 万字符），超限时给出本地化提示而不是发请求。
- 模型发现走 `@deepseek-ai/dsh-llm` 的正式接口：`listProviders()` 列出已注册的路由，再对每个 provider 调 `listModels(providerId)`。`listModels` 必须带 provider id，无参调用会抛 `NO_ADAPTER`——这正是「挨个调用长得像列举的方法」在现行宿主上一个模型都发现不到的原因。某个 provider 列举失败只会写进 `modelFailures`，不影响其它 provider。结果缓存 60 秒并在 `llm/adapters-updated` 时失效，所以在「设置 → 模型」里加了 provider 不用重启就能出现在下拉框里。只有请求带 `route` 时才会为发现付出开销。
- 可见 provider 多于一个时，下拉框用 `optgroup` 按 provider 分组；`default` 那一项取的是档案的默认选择而不是当前路由，所以切换之后它仍然显示真正的默认模型。
- `.docx` 读取是一个小 ZIP 遍历器（中央目录 → 本地头 → `DecompressionStream(deflate-raw)`），再加一层 `word/document.xml` 去标签；页眉页脚和批注刻意不管。HTML 用正则解析，所以没有 DOM 的 Node 测试环境也能跑。
- 评分默认隐藏是刻意设计：只有显式请求才获取，开关可以再次收起。
- 开机打开“最近使用”的文档，而不是置顶的首条；打开旧稿不会更新它的时间，编辑才会。
- 历史裁剪先丢最旧的未置顶条目，所以置顶文档不会被数量或字符预算挤掉。
- 修改记录存的是“改动之前”的文档，且只在它与最新快照不同时才写入，所以一次批量优化只多一条；回退时先把即将被覆盖的译文存一份，这正是回退可以撤回的原因。
- 改页面样式时注意 CSS 写在模板字符串里：CSS 注释中出现反引号会截断字面量。自查办法是数反引号（应为 0）并比较 `{` 与 `}` 数量是否相等。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 头部显示 `翻译服务未就绪` | 设置里没有选默认模型，或供应商暂时不可达。选好默认模型后刷新页面。 |
| 头部没有模型下拉框 | 只发现了一个可用路由，没有可切换的对象。编辑器上方会提示是哪个 provider 列举失败；也可以在插件配置里补 `models` 手工兜底。 |
| 提示 `当前模型不支持图片识别`（HTTP 422） | 当前模型不支持读图，换一个支持图片的模型。 |
| 导入 `.docx` 时提示浏览器无法解析 | 该浏览器没有 `DecompressionStream`。把文件另存为 `.txt`、`.md` 或 `.html` 再导入。 |
| 下载的 HTML 丢了样式和链接 | 这是预期行为：页面翻译的是文字，导出只保留段落。需要排版请保留原文件。 |
| 点 `新建翻译` 后以为文档没了 | 文档仍在历史里，页面只是切到空白表单；点头部文档入口切回去即可。 |
| 回退后想找回刚被覆盖的译文 | 回退前已把它存成 `回退前` 一条记录，再打开 `修改记录` 回退那一版即可。 |
| 清除浏览器数据后历史消失 | 历史和编辑只存在 `localStorage`，没有云端副本。 |
